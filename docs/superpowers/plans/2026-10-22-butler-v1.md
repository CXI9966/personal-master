# Butler v1 桌面端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 Butler 桌面客户端 v1：本地数据、打卡与任务、GitHub 式热力图、可接任意模型接口的管家 AI、提醒与安装包。

**Architecture:** 数据逻辑全在 Electron 主进程。store、domain、render、ai 都是不 import electron 的纯模块，时钟和密钥存储靠注入，方便单测。界面是 React，只通过类型化的 IPC 和 `window.butler` 调主进程。所有读写和追加走同一个队列，先写临时文件再整体替换。

**Tech Stack:** Electron 44.7.0、electron-vite 5.0.0、Vite 7.3.7、@vitejs/plugin-react 5.2.0、React 19.3.0、TypeScript 6.0.3、zod 4.6.5、chokidar 5.0.0、date-fns 4.4.0、ai 7.0.132 + @ai-sdk/openai-compatible 3.0.65 + @ai-sdk/anthropic 4.0.75、Vitest 5.0.3、Playwright 1.64.0、electron-builder 26.17.0、@types/node 24.19.1。依赖一律精确版本。

## 写法说明

这是精简版计划：每个任务只写要建的文件、对外接口、要测的情况和验收命令，代码在动手时按设计文档写。需求以 [设计文档](../specs/2026-10-22-butler-design.md) 为准。

已经验证过的资料，动手前先读对应部分：

- [工具链验证](../notes/toolchain-verified.md)：脚手架的全部配置。
- [基础库验证](../notes/spike-libs.md)：zod、chokidar、date-fns 的用法，原子写和逻辑日期的可用实现，末尾有 26 条坑。
- AI SDK 7 还没验证过，任务 7 的第一步就是验证。

每个任务都按同一个节奏：先写测试并看它失败，再实现，`npm run typecheck` 和 `npm test` 通过后提交（conventional commits）。碰到主进程或界面的任务，再跑一遍 `npm run test:e2e`。

## 不能少的环节

1. 写入安全：队列、原子替换、坏行容错、50 次撤销（任务 2）。
2. 日期归属：凌晨 4 点换日、同日多次打卡的取舍、ISO 周（任务 3）。
3. AI 只能通过校验过的动作改数据，大改要确认，失败时不写任何东西（任务 7）。
4. API key 加密保存，不进工作区（任务 5、8）。
5. 每个任务先写测试；主流程有 Playwright 端到端（任务 1、5、6、8）。
6. 安装包装一遍实测（任务 10）。

## 里程碑

- M1（任务 1 到 6）：不带 AI 的完整可用版本，做完就能日常使用。
- M2（任务 7 到 8）：管家 AI。
- M3（任务 9 到 10）：周报、提醒、自启、安装包。

要压缩体量的话，按这个顺序砍：JSON 文本兜底 → "自己按需查"策略 → 提醒 → 周报点评。它们都放在各任务的最后一步，砍掉不影响其他部分。

### Task 2: 数据层（store）

**Files:** src/shared/schema.ts（先放文件相关的 schema，其余在任务 3 补）、src/main/store/{queue,atomic,jsonl,history,watcher,workspace}.ts、tests/unit/store/*

```ts
export interface Workspace {
  readJson<T>(rel: string, schema: ZodType<T>): Promise<T>
  writeJson<T>(rel: string, value: T, schema: ZodType<T>): Promise<void>
  appendLine<T>(rel: string, value: T, schema: ZodType<T>): Promise<void>
  readLines<T>(rel: string, schema: ZodType<T>): Promise<{ items: T[]; skipped: { line: number; reason: string }[] }>
  // 一次改动 = 一个队列任务，可以写多个文件；fn 里的写入共用一条历史，撤销时整体回退。tx 内部不再排队，避免死锁
  batch<T>(label: string, fn: (tx: Pick<Workspace, 'readJson' | 'writeJson' | 'appendLine'>) => Promise<T>): Promise<T>
  lastChange(): { id: string; label: string } | null // 最近一次可撤销的改动
  undo(changeId: string): Promise<boolean>           // 只有它还是最近一次改动时才成功
  restoreFromHistory(rel: string): Promise<boolean>  // JSON 文件整个解析失败时，恢复成最近一份历史快照
  onExternalChange(cb: (rel: string) => void): () => void
  close(): Promise<void>
}
export function openWorkspace(root: string, deps?: { now?: () => Date }): Promise<Workspace>
```

要点（细节见 spike-libs 第 3、5 节和坑 2 到 7、10、18 到 22）：
- 读、写、追加走同一个队列：同进程的读也会让 Windows 的 rename 失败。
- 原子写：临时文件 → fsync → rename；遇到 EPERM/EBUSY/EACCES 退避重试（5 ms 起，50 ms 封顶，±50% 抖动，最多 10 s），超时抛错并保住待写数据。直接用 spike-libs 5.3 的实现。
- JSONL 读取去 BOM，坏行跳过并返回行号。JSON 用 `z.looseObject`，保留用户手加的字段。
- 每次改动前，把文件当前内容存进 `data/.history/`，只留最近 50 次改动。JSONL 追加类文件只记追加前的文件长度，撤销时截断，不整份复制。
- 监听：不用 glob；忽略 `.tmp` 和 `.history`；写之前先登记"这是自己写的"；add 和 change 一样处理；500 ms 防抖。

- [ ] 先写测试：200 次并发 writeJson 不丢不坏；目标被另一个读取流占着时重试成功；持续占用到超时（测试里缩短超时）抛错且数据保留；100 次并发 appendLine 不交错；坏行、BOM、空文件；JSON 内容损坏时 readJson 抛出带文件名的错误，`restoreFromHistory` 能恢复上一份；写 3 次撤销 3 次回到初始，写 60 次只留 50 次；一个 batch 写两个文件，撤销后两个都回退；追加后再有新改动，旧改动撤销返回 false；JSONL 撤销后恰好回到追加前的内容；自己写的不触发外部变更，外部改文件会触发；中文目录和文件名。
- [ ] 实现，`npm run typecheck && npm test` 通过。
- [ ] 提交：`feat(store): queued atomic workspace with undo and watcher`

### Task 7: 管家 AI 核心

**Files:** src/shared/actions.ts、src/main/ai/{provider,context,prompt,actions,runner,usage}.ts、docs/superpowers/notes/ai-sdk-verified.md、tests/unit/ai/*

第一步先验证（在临时目录里，不碰仓库，只信 `.d.ts` 和亲手跑通的代码），结果写进 `notes/ai-sdk-verified.md`：
1. 两种 provider 的创建方式和 baseURL 拼接规则（要不要带 `/v1`）。
2. `streamText` 的参数；工具怎么定义（`inputSchema` 还是 `parameters`）、怎么配合 zod 4；不让 SDK 自动执行工具时，怎么拿到调用、怎么把结果回传。
3. 流式读取文本和工具调用的方式；`usage` 的字段名；中途中断的表现。
4. 401、429、500 和断网时抛出的错误类型，怎么区分。
5. 用 `node:http` 写本地模拟服务器（OpenAI 兼容的 SSE 和 Anthropic 的 SSE 各一份，含一次工具调用），后面的测试都用它。

然后实现：
- 动作注册表（zod 参数 + 级别）。小改直接执行：add_task、update_task、complete_task、add_plan_item、save_review、record_learning_check、log_weight、log_workout。大改要确认：set_day_plan、delete_task、reschedule_tasks、update_profile。模型不能指定文件路径，不能写打卡记录。
- 一次回复里的动作，等回复结束且全部校验通过才执行；校验失败的把错误发回模型重试一次，仍失败就告诉用户。小改用 `store.batch` 执行，动作卡片的"撤销"调用 `store.undo`；它只在该动作还是最近一次改动时可用，之后有新改动就置灰。大改先生成确认卡片列出具体改动。
- 上下文三种策略：scene（默认）、full、tools（只读查询 get_tasks、get_plan、get_records、get_profile）。系统提示词按"固定规则 → 管家人格.md → 上下文 → 当前时间"拼。
- 人格文件按四个二级标题解析；标题被改乱就把全文当成一个整体使用。
- 每次调用往 `usage.jsonl` 记 token 数，接口没返回就记 null。
- 最后一步 JSON 文本模式：模型不支持工具调用时，系统提示词附动作清单（`z.toJSONSchema`），解析回复末尾的 json 代码块，走同样的校验；这个模式下 tools 策略自动退回 scene。

- [ ] 先写测试（全用本地模拟服务器，不调真实接口）：两种接口各走一遍；小改直接生效并可撤销；大改没确认就不生效；参数校验失败重试一次；回复中途断开不执行任何动作；三种上下文策略的组装结果快照；没配置接口时报明确的错误。
- [ ] 实现，`npm run typecheck && npm test` 通过。
- [ ] 提交：`feat(ai): provider factory, action registry and context strategies`
