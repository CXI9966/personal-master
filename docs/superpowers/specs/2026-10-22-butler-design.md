# Butler 客户端设计

- 日期：2026-10-22
- 状态：已确认（用户逐项选择确认）
- 代码仓库：https://github.com/CXI9966/personal-master
- 范围：v1 桌面端；v2 手机打卡与同步（本文先把接口定下来）

## 1. 背景

- 旧 Butler 由 Claude Code、Markdown 文件和 PowerShell 计划任务组成，2026-09-07 之后就没再被使用。
- 失败原因：用起来麻烦（开终端、等大模型、每天三次固定流程）；反馈只有越积越多的"缺勤"；启动器 `claude --continue` 续接到考勤脚本 `claude -p` 存下的会话；计划任务在电脑刚唤醒时检测网络，93 次没到里有 55 次被误记为"断网"；补跑的检查写错日期，并发写入产生重复行。
- 2026-10-22 按用户要求清空旧工作区，从头重建。

## 2. 目标与不做的事

目标：

1. 打卡、勾任务、记体重和健身这类操作点一下就完成，不等 AI，不需要联网。
2. 用 GitHub 式日历热力图展示每天做了多少。只统计做到的，不记"缺勤"。
3. 管家 AI 能接任意模型接口（OpenAI 兼容或 Anthropic），只能通过有类型的"动作"改数据。
4. 数据分两份：程序读写 data/ 下的 JSON/JSONL（原始数据），给人看的 Markdown 由程序生成。
5. 做成可复用的软件：不写死路径和个人信息，工作区在第一次运行时选择。

v1 不做：手机 App 与同步（放 v2）、云端中转、多用户、手机提醒、自动备份、数据库、按功能分配不同模型、花费上限、多语言界面、后台自动调用 AI。

## 3. 总体结构

```
桌面端界面（React） ◀─IPC─▶ 桌面端主进程（Node）
                              ├─读写──▶ 工作区：data/（原始数据）+ 生成的 .md
                              ├─HTTPS─▶ 模型接口（OpenAI 兼容 / Anthropic）
                              └─局域网（v2）◀── 手机 App
```

技术栈：Electron + Vite + React + TypeScript；electron-builder 打 NSIS 安装包；Vercel AI SDK（`ai`、`@ai-sdk/openai-compatible`、`@ai-sdk/anthropic`）；zod 做参数校验；chokidar 监听文件；Vitest 和 Playwright 做测试。实现时锁定精确版本，只选发布满两周的版本。

主进程按职责分成几个模块，模块之间只通过类型化接口调用：

| 模块 | 职责 |
|------|------|
| store | 工作区读写、写入队列、原子替换、撤销历史、文件监听 |
| domain | 任务、计划、打卡、记录、学习检验、热力图计分；纯函数，便于单测 |
| render | 从 data/ 生成 Markdown 视图 |
| ai | 模型接口适配、上下文组装、动作校验与执行、用量记录 |
| scheduler | 跨日处理、周报生成、提醒 |
| shell | 托盘、开机自启、通知、单实例锁、设置与密钥 |
| sync（v2） | 给手机用的局域网接口 |

界面页面：今日、任务、管家、记录、设置。

## 4. 工作区与数据

### 4.1 目录

```
<工作区>/
├── 管家人格.md            手写原始数据：管家人格，分栏
├── 课表.md                手写原始数据：自由文本，原样交给模型
├── 今日.md                生成
├── 本周.md                生成
├── 我的设定.md            生成：目标和固定安排
├── 任务库/<清单>.md        生成：每个清单一个文件，默认清单"收集箱"
├── 记录/                  生成：打卡.md、体重.md、健身.md、学习.md
├── 归档/<年>/<年-W周>/     生成：每天一份（计划+复盘）和 周报.md
└── data/                  程序读写的原始数据
    ├── profile.json       目标和固定安排（栏目齐全，值全空）
    ├── settings.json      非敏感设置
    ├── tasks.json         任务库当前状态
    ├── plans/<日期>.json   当天计划、精力和复盘
    ├── checkins.jsonl     起床/睡前打卡
    ├── weight.jsonl       体重
    ├── workouts.jsonl     健身
    ├── learning.jsonl     学习检验
    ├── usage.jsonl        每次 AI 调用的 token 数
    └── .history/          撤销用：最近 50 次改动前的文件内容
```

- 生成的 .md 第一行固定为：`> 由 Butler 客户端根据 data/ 生成，改这里会被覆盖。要改请在客户端里改。`
- 工作区里的其他文件（比如 .git、启动脚本）程序一概不碰。
- 文件一律 UTF-8 无 BOM、LF 换行；JSON 缩进 2 个空格，JSONL 一行一条。
- 每个 JSON 文件带 `"version": 1`，以后改格式时按版本迁移。
- 编号用 UUID v4；学习检验另有顺序号 `L-0001`，方便人看。
- API key 不进工作区：用 Electron safeStorage（Windows DPAPI）加密后，存在应用自己的数据目录。应用数据目录里还记着当前工作区的路径。

### 4.2 第一次运行

1. 选工作区文件夹，默认 `文档\Butler`，也可以选已有文件夹。
2. 选一个人格预设（见 6.2）。
3. 填模型接口，可以跳过；跳过时 AI 功能置灰。
4. 创建 data/ 下的空文件、`管家人格.md`、只有标题的 `课表.md`，以及全部生成的 .md。

### 4.3 记录格式（JSONL，只追加）

```jsonc
// checkins.jsonl：type 为 wake / sleep，source 为 desktop / phone
{"id":"…","type":"wake","at":"2026-10-23T07:02:11+08:00","source":"desktop"}
// weight.jsonl
{"id":"…","at":"2026-10-23T07:10:00+08:00","kg":76.5}
// workouts.jsonl
{"id":"…","at":"2026-10-23T21:20:00+08:00","summary":"有氧 30 分钟 + 力量","durationMin":65}
// learning.jsonl：result 为 mastered / partial / missed
{"id":"…","seq":1,"at":"…","taskId":"…","topic":"示例主题","checks":[{"q":"…","result":"partial"}]}
// usage.jsonl：feature 为 plan / review / chat / weekly
{"id":"…","at":"…","provider":"openai-compatible","model":"…","feature":"chat","inputTokens":1830,"outputTokens":240}
```

### 4.4 状态文件（JSON，整体替换）

```jsonc
// tasks.json：status 为 open / done / dropped
{"version":1,"lists":["收集箱"],"tasks":[{"id":"…","title":"…","list":"收集箱","status":"open",
  "createdAt":"…","doneAt":null,"due":null,"checkpoints":[],"notes":""}]}
// plans/2026-10-23.json：energy 为 high / mid / low；review 复盘后填写
{"version":1,"date":"2026-10-23","energy":null,
  "timeline":[{"start":"09:00","end":"10:30","title":"…","taskId":null}],
  "taskIds":[],"review":null}
// review 填写后的样子
{"done":"…","learned":"…","change":"…","at":"…"}
// profile.json：全部留空，由用户填
{"version":1,"goals":{"weightTargetKg":null,"notes":""},
  "schedule":{"wakeTarget":null,"sleepTarget":null,"gymDays":[],"fixed":[]}}
// settings.json
{"version":1,"dayStartsAt":"04:00",
  "provider":{"kind":"openai-compatible","baseURL":"","model":""},
  "contextStrategy":"scene","actionMode":"tools",
  "heatmap":{"weights":{"checkin":1,"taskDone":1,"weight":1,"workout":1,"review":2,
    "learnMastered":3,"learnPartial":2,"learnMissed":1}},
  "reminders":{"enabled":false,"plan":null,"review":null}}
```

- `schedule.fixed` 是每周固定安排，每项形如 `{"weekday":1,"start":"08:00","end":"09:40","title":"…"}`，weekday 1 到 7 对应周一到周日。
- 计划和任务分开存：计划只引用任务编号。计划过了日期，没完成的任务仍留在任务库里。

### 4.5 写入规则

- 所有写入都进主进程的同一个队列，一次只执行一个。
- JSON 状态文件先写临时文件，再整体替换；JSONL 只在末尾追加一行。
- 读 JSONL 时跳过不完整或解析失败的行，在界面上提示文件名和行号。
- 每次改动前，把要改的文件当前内容存进 `data/.history/`，只留最近 50 次。撤销就是把文件恢复成那份内容，再重新生成 .md。
- 数据变化后延迟 500 毫秒，重新生成受影响的 .md。
- 监听 `管家人格.md`、`课表.md` 和 data/ 的外部改动，自动重新加载。生成的 .md 被手动改了不读回，下次生成时覆盖。
- 用单实例锁保证同一时间只有一个客户端在写。

## 5. 每天怎么用

- 日期归属：一天从 `dayStartsAt`（默认凌晨 4:00）开始，00:30 点"睡前"算前一天。
- 起床：在托盘菜单或今日页点"起床"，记一条 wake（v2 起也可以在手机小组件上点）。同一天多次点都会记下，显示、统计和计分只算第一次。
- 晨会（可跳过）：今日页列出今天的固定安排、课表和没完成的任务，选精力档位。可以手动排；也可以点"让管家排"，管家给出整天的时间安排，作为大改动等你确认，确认后写入当天计划。
- 白天：勾任务、加任务、记体重和健身，都不调 AI。托盘菜单里有起床/睡前打卡和今天的任务，点任务就勾掉。
- 复盘（可跳过）：过一遍今天的任务（完成 / 没完成 / 挪到明天），写三句话：完成了什么、学会了什么、明天改什么。当天有学习任务时，管家按人格里的检验规则问 1 到 3 个开放问题，结果写入 learning.jsonl。
- 睡前：点"睡前"，记一条 sleep。同一天多次点都会记下，显示、统计和计分只算最后一次。
- 提醒：只在客户端运行时发 Windows 通知。晨会提醒在设定时间还没有当天计划时发；复盘提醒在设定时间还没复盘时发；每样每天最多一次，语气平和。默认关闭，设了时间才开启。
- 隔了 3 天以上再打开：只显示"欢迎回来"，不列出没做的事。
- 统计一律正向口径，例如"本周起床打卡 4/7 天，平均 07:12；复盘 3 次"。界面和生成的文件里都不出现"缺勤""断网"。
- 周报：进入新的一周（每周从周一开始算）后第一次运行时，生成上一周的 `归档/<年>/<年-W周>/周报.md`，内容包括打卡次数和平均时间、完成任务数、体重变化、健身次数、学习检验结果、热力图分数、本周 token 用量。生成周报不调 AI；周报页有"让管家点评"按钮，点了才调用。

## 6. 管家 AI

### 6.1 接口

- 设置里填：接口类型（OpenAI 兼容 / Anthropic）、接口地址、模型名、API key，并提供"测试连接"按钮。
- 没配置时 AI 功能置灰，其他功能照常可用。
- 只在用户主动发起时调用：让管家排、复盘检验、聊天、周报点评。

### 6.2 人格

- 内置三种预设：战友教练、温和陪伴、严格教官。第一次运行时选一个，生成 `管家人格.md`。
- 文件固定四栏（二级标题）：说话风格、督促方式、检验规则、不许做的事。客户端按栏目编辑；用户把标题改乱了，就把全文当成一个整体使用。
- "战友教练"沿用旧系统人格里的通用部分：语气有温度、肯定进步；懈怠时先关心原因再督促；检验不放水；只问"为什么 / 如果…会怎样 / 讲给外行听"这类开放问题，不问"是不是 / 对不对"。
- 每个预设的"不许做的事"都默认包含：不翻旧账、不贬低、不编造用户没做过的记录。

### 6.3 系统提示词

按顺序拼接：

1. 客户端固定规则（用户不能改）：用中文回复；只能通过动作改数据，没执行动作就不能说"已经改好"；时间按本地时区；回复简短。
2. `管家人格.md` 全文。
3. 按上下文策略组装的内容（见 6.4），加上当前日期和时间。

### 6.4 上下文策略（设置里三选一，默认按场景）

- 按场景（scene）：
  - 晨会：固定安排、课表、未完成任务（最多 30 条）、最近 7 天打卡摘要、精力档位。
  - 复盘：当天计划和任务状态、当天的学习任务及检验点。
  - 聊天：今天的概况（计划、完成数、打卡）。
- 完整概况（full）：每次都带目标和固定安排、本周计划、最近 7 天的全部记录。
- 自己按需查（tools）：只带今天的概况，另外提供只读查询工具 get_tasks、get_plan、get_records、get_profile。

### 6.5 动作

动作参数用 zod 定义，模型通过工具调用提出，客户端校验通过后才执行。模型不能指定文件路径，也不能写打卡记录。

| 动作 | 级别 |
|------|------|
| add_task、update_task、complete_task | 小改，直接执行 |
| add_plan_item、save_review | 小改，直接执行 |
| record_learning_check、log_weight、log_workout | 小改，直接执行 |
| set_day_plan（替换整天计划） | 大改，要确认 |
| delete_task、reschedule_tasks（批量改日期） | 大改，要确认 |
| update_profile（改目标或固定安排） | 大改，要确认 |

- 小改执行后，在对话里显示一张卡片，带"撤销"按钮。
- 大改先显示确认卡片，列出具体改动，用户点"确认"才执行。
- 一次回复里的动作在回复结束、全部校验通过后才执行。校验失败的动作不执行，把错误发回给模型重试一次，仍失败就告诉用户。
- 动作模式（设置）：默认"工具调用"。模型不支持工具调用时切换成"JSON 文本"：系统提示词里附上动作清单和参数说明，让模型在回复末尾输出一个 json 代码块，客户端解析后走同样的校验。JSON 文本模式下"自己按需查"不可用，自动改用"按场景"。

### 6.6 用量

- 每次调用把接口返回的 token 数写进 usage.jsonl，接口没返回就记 null。
- 周报和设置页显示本周按功能、按天统计的 token 用量。不设上限，也不换算成金额。

### 6.7 失败处理

- 网络或接口出错：在对话里显示错误和"重试"按钮，不写入任何数据。
- 回复中途断开：已经显示的文字保留，动作一律不执行。

## 7. 日历热力图

- 每天的分数是当天各项动作的分数之和。默认权重：起床、睡前打卡各 1 分；完成一个任务 1 分；记体重每天最多 1 分；每次健身 1 分；复盘 2 分；学习检验掌握 3 分、部分掌握 2 分、没掌握 1 分。权重在设置里可以改。
- 分档跟自己比：分数为 0 的日子显示空格。过去 365 天里分数大于 0 的日子，按四分位分成四档颜色：不超过第一四分位为 1 档，不超过中位数为 2 档，不超过第三四分位为 3 档，更高为 4 档。数据很少时，偶尔一天就可能到最深色，这是用户接受的取舍。
- 今日页顶部显示最近 12 周（每列一周，从上到下是周一到周日），点击后在记录页展开全年。点某个格子，显示那天的计划、完成的任务、打卡、记录和复盘。
- 每个格子都带文字说明（日期和分数），不靠颜色也能读出数值；颜色对比度要保证看得清。

## 8. 出错处理

- 写入：见 4.5。
- 读到坏数据：跳过坏行并提示，不崩溃。JSON 状态文件整个解析失败时，提示用户，并提供"恢复到上一个版本"（取自 `data/.history/`）。
- 撤销：最近 50 次改动可撤销。按用户选择，不做自动备份。
- AI：见 6.7。
- 时间：所有时间带时区偏移存储，统计时按 `dayStartsAt` 归到某一天。

## 9. 测试

- Vitest 单元测试：
  - store：追加、原子替换、坏行容错、写入队列顺序、撤销。
  - domain：日期归属（4:00 边界）、同日多次打卡的取舍、热力图计分和分档、统计口径。
  - render：每种生成的 .md 做快照测试。
  - ai：动作参数校验、大小改动分级、确认流程、三种上下文策略的组装结果、JSON 文本模式的解析。模型接口用本地模拟服务器，不调用真实接口。
- Playwright（Electron）走通主要流程：
  - 第一次运行：选工作区和人格 → 打卡 → 勾任务 → 热力图更新。
  - 用模拟模型聊天：小改动卡片 → 撤销；大改动 → 确认后生效。

## 10. 分期

v1（桌面端）：

1. 项目骨架、store、domain、render 和第一次运行的初始化。
2. 今日、任务、记录、日历页面和托盘打卡。
3. 管家 AI：设置、人格预设、对话、动作、上下文策略、用量统计。
4. 提醒、周报、开机自启和安装包。

v2（手机）：

1. 先验证：电脑连上手机热点后，手机能否把 HTTP 请求发到电脑（包括 Windows 防火墙"公用网络"的放行）。
2. 桌面端同步接口。
3. 安卓 App：桌面小组件、本地存储、后台同步、配对。

## 11. 手机同步（v2，接口先定）

- 网络：电脑连手机热点，由手机主动推送给电脑。
- 配对：电脑显示 6 位配对码，5 分钟内有效。手机在热点网段里找到电脑，提交配对码，换回一个长期口令（32 字节随机数）。口令在电脑上用 safeStorage 加密保存，在手机上用 Android Keystore 加密保存。
- 找电脑：先试上次成功的地址；不通就扫描热点网段（/24）里的固定端口，每个地址的连接超时设得很短。
- 接口：
  - `GET /v1/ping`，返回 `{"app":"butler","version":"…"}`。
  - `POST /v1/checkins`，请求头带 `Authorization: Bearer <口令>`，请求体 `{"events":[{"id":"…","type":"wake","at":"…"}]}`，返回 `{"accepted":[…],"duplicates":[…]}`。手机把这两类都标记为已同步。
- 安全：没有口令一律返回 401；只接受私有网段的请求；只有这一个写接口，不能读写其他文件；做简单限速。
- 同步时机：点小组件时、打开 App 时、WorkManager 每 15 分钟一次。
- 手机端不依赖谷歌服务。
- Windows 会把手机热点识别为公用网络：安装程序添加一条只放行本地网段的入站规则；做不到时，第一次运行提示用户在防火墙弹窗里勾选"公用网络"。

## 12. 风险

- 手机热点下电脑能否被手机访问还没实测，v2 第一步先验证。
- 华为可能推迟后台任务，靠多个同步时机弥补。
- 不同模型调用工具的能力差别大，用 JSON 文本模式兜底。
- 没有自动备份，数据只靠撤销保护。
