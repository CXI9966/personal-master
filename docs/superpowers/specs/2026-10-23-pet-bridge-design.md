# 桌宠接入设计

- 日期：2026-10-23
- 状态：设计已确认。用户同时要求：许可证改成不可商用、加一个桌宠风格的管家人格、台词用模型写但要限频
- 范围：Butler 作为 dsh-pet 的客户端，通过它的本机 HTTP 接口，让桌宠反映 Butler 的状态、提供右键菜单入口、说管家台词
- 依据：dsh-pet v0.3.8 仓库里的 `API.md` 和 `openapi.yaml`。写文档时没有运行过它，真机细节以验证为准

## 1. 背景与边界

- dsh-pet 是 DeepSeek Harness 的桌宠插件。接口前缀 `/dsh-pet-7340`，默认端口 3080，没有鉴权，只监听本机。
- Butler 是客户端：自己不开端口；桌宠没装、没开时静默跳过，Butler 照常工作。
- 不改 dsh-pet，不带它的素材（素材禁止商用）。
- 前提是用户自己运行 dsh-pet（`dsh-pet-standalone`，或装进 dsh）。独立运行时它没有模型，聊天和碎碎念不可用，本设计用到的接口都可用。

## 2. 用到的接口

所有动作都带 `pet=<宠物 id>&surface=any`。

| 用途 | 接口 |
| --- | --- |
| 连接测试 | `GET /config`（取宠物 id 列表）、`GET /state`（探活） |
| 常驻状态 | `POST /work-status {state, task}`、`DELETE /work-status` |
| 台词 | `POST /broadcast {text, duration}`；被要求占用锁时先 `POST /lock`，用完 `POST /lock/release` |
| 右键菜单 | `POST /menu/item {owner, labels}`、`GET /menu/events?owner&wait`、`DELETE /menu/item?owner` |

`API.md` 把 `/broadcast` 标成“需锁”，`openapi.yaml` 的 `lock` 参数说明又写“当前没有占用时可以不带”。实现先不带锁，对方回 `lock-required` 才取锁。

真机验证（dsh-pet 0.3.8 独立运行）的结果，文档里没写：

- `/broadcast` 不带锁就被接受，锁叶子保持为空，说话时桌宠不会被冻住。
- 独立运行时，所有写请求（POST、DELETE）都要带请求头 `x-dsh-pet-token`，读请求不用。令牌每次启动随机生成，写在 `$DSH_HOME/dsh-pet/standalone-runtime.json`（没设 `DSH_HOME` 就是用户目录下的 `.dsh`）里，内容有 `port` 和 `token`。
- Butler 每次请求前读这个文件，只在文件里的端口和接口地址的端口一致时才发送令牌，免得把令牌发给别的服务；读不到就不带，对方回 403，试连会提示是令牌的问题。
- 装进 DSH 里运行的 dsh-pet 按文档没有鉴权，没有这个文件。这一种没有实测。

## 3. 设置（这台电脑的设置，存 `config.json`，不进工作区）

设置页新增“桌宠”一栏：

- 启用桌宠（默认关）。
- 地址，默认 `http://127.0.0.1:3080/dsh-pet-7340`。只接受 `localhost`、`127.0.0.1`、`[::1]`，避免把任务名发到别处。
- 宠物 id，默认 `main`。
- 四个开关，默认都开：状态、右键菜单、台词、用模型写台词。
- 模型台词的最短间隔（分钟），默认 10，范围 1 到 240。
- “测试连接”按钮。

## 4. 事件从哪来

不改每个服务，从数据变化里推导。数据变化后（`notifyDataChanged`，防抖 0.7 秒）读一次今日摘要：起床和睡前是否打卡、是否排了计划、是否复盘、今天完成了几个任务。和上一次比较，变了才算事件：起床打卡、睡前打卡、完成任务、排好计划、复盘完成。

- 启动、换工作区、换日时只记基线，不产生事件。
- 隔了几天才回来（今日摘要的 `welcomeBack`）：每个逻辑日在记基线时说一次。
- 提醒到点：定时检查弹系统通知时同时通知桌宠（提醒带上种类 `plan` 或 `review`）。
- 管家回复和出错：发送时开始，收到 `done` 结束，收到 `error` 报错。

## 5. 桌宠怎么反应

- 常驻状态（`work-status`），优先级从高到低：提醒了还没办 = `waiting`，管家出错 = `error`（10 秒），管家在回复 = `thinking`，其余清空（`DELETE`）。状态变了才发。
- 一次性台词（`broadcast`，约 8 秒）：同时最多一句，新的覆盖排队中的旧的；两句至少隔 3 秒。取锁被别的程序占着就放弃这句，不排队。
- 关掉“台词”时，一次性事件改为 `success` 加一句固定短语，10 秒后回到常驻状态。

## 6. 台词用模型，限频

这是对“不在后台自动调用模型”这条原则的有意例外，由用户决定。

- 事件发生时先判断限频：距离上次模型台词不到最短间隔，或这一小时已经 6 次，就直接用本地模板，桌宠马上有反应。
- 限频放行时，让模型写一句：用管家人格做 system，加上事件事实，要求一句话、不超过 24 个字、不编造。8 秒超时或失败就退回模板。
- 模型没配置好（没地址、模型名或 key）时只用模板。
- 调用量记在用量里，名下是“桌宠台词”，设置页的“本周用量”能看到。
- 模板按人格分五套：战友教练、温和陪伴、严格教官、蓝鲸桌宠，对不上预设的用中性。比对的是 `管家人格.md` 里“说话风格”一栏。

## 7. 蓝鲸桌宠人格

给管家人格新增第四个预设 `whale`（蓝鲸桌宠）：赖在桌面上的蓝色大鲸鱼，爱碎碎念、爱提零食和打盹，该督促的事一件不落。内容原创，不使用 dsh-pet 的文案和素材。第一次运行页和设置页的人格预设列表会自动出现它。

## 8. 右键菜单

在桌宠右键菜单的“更多”下注册 owner `管家` 的几项，数据和托盘共用 `buildTrayModel`：起床打卡、睡前打卡、最多 5 个“完成：任务名”、打开 Butler。点击靠长轮询 `menu/events` 拿到，用 `performTrayAction` 执行，所以和托盘行为一致，也会触发状态变化和台词。菜单文案变了（任务变了、打卡了）才重新注册。

## 9. 健壮性与隐私

- 每次调用超时 1.5 秒（长轮询除外），失败只记一次警告，不打扰界面。
- 连不上时每 30 秒探测一次；恢复后重新注册菜单、补发常驻状态。
- 启动（连上后）和退出时清掉自己写的状态、菜单项和锁，避免异常退出后桌宠一直“等待”。
- 只发短句和截断到 20 字的任务名；不发工作区路径和密钥。发给模型的只有事件事实。

## 10. 验证

不往仓库加测试文件。

1. 一次性脚本启动一个假的桌宠服务器，按接口文档实现并记录请求，再驱动真实的 Electron：打卡、勾任务、提醒、管家对话、右键菜单点击、断开重连、关闭桌宠。
2. 经用户同意后，在临时文件夹里装一份真的 dsh-pet 独立运行，用 Butler 自带的 Electron，目视确认。

## 11. 许可证

Butler 改用 PolyForm Noncommercial 1.0.0（已提交）。已发布的 MIT 提交仍在历史里，那一刻拿走的副本保持 MIT；此后的版本按新许可证。

## 12. 自动启动（用户后来加的要求）

用户要求“打开 Butler 时自动下载桌宠”。评估了三种做法：用 npm 下载锁定版本、随安装包带一份、只自动启动不下载。用户选了第三种：Butler 不下载，不运行任何自己拉来的第三方代码，只负责启动用户已经装好的桌宠。

- 设置新增 `launcher`（启动文件的完整路径，`.bat`、`.cmd` 或 `.exe`）和 `autoStart`。保存时检查：必须是盘符开头的绝对路径、扩展名合法、路径里没有 `< > | * ? " % & ^`（`.bat` 经 `cmd.exe /c` 执行，这些字符会被 cmd 解释）。
- 打开 Butler 时，桌宠接入已启用且 `autoStart` 为真，就调用 `ensure`：
  1. 接口地址已经连得上：状态 `external`，直接用，不启动第二个，退出时也不关它。
  2. 没填启动文件，或文件不存在：状态 `missing`，说明原因，不启动。
  3. 否则隐藏窗口启动，状态 `starting`；每 0.5 秒探一次，连上了变 `started` 并立刻通知桥接去连接，不用等 30 秒一次的探活；一分钟还连不上变 `failed`，带上启动文件最后一行输出。
  4. 启动文件很快以非 0 退出，变 `failed`；以 0 退出的当作交给了别的进程，继续等。
- 退出 Butler 时先让桥接清掉自己在桌宠上的状态和菜单项，再用 `taskkill /T /F` 结束 Butler 自己启动的那个进程树。关掉桌宠接入时同样处理。
- 设置页隔 2 秒问一次 `pet:status` 显示进展；“现在启动桌宠”按钮按已保存的启动文件启动，改过没保存时是灰的。
- 验证：隔离的测试桌宠（端口 3181，窗口关掉）加真实 Electron，18 项通过，覆盖自动启动、直接用、退出时只关自己启动的、文件不存在、非法路径、保存时联动、关闭时联动。
