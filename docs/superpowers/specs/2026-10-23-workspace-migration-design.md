# 工作区迁移设计

- 日期：2026-10-23
- 状态：设计已确认（用户选择“按这个设计做”），待用户审阅本文
- 范围：在设置页把工作区迁移到别的文件夹，或切换到已有的工作区
- 关联：[Butler 客户端设计](2026-10-22-butler-design.md) 第 4 节

## 1. 背景

- 工作区路径只记在应用数据目录（`%APPDATA%\butler\config.json`）里，设置页只显示路径，没有修改入口。
- 代码里已有选文件夹（`workspace:pick`）、检查文件夹（`workspace:inspect`）、打开已有工作区（`workspace:open`），缺的是“把数据带到新位置”这一步。
- 用户要求：工作区可以迁移，入口直接放在设置里。

## 2. 目标与不做的事

目标：

1. 设置页一步完成：选新文件夹、复制、校验、切换。旧文件夹保留，由用户自己决定删不删。
2. 选到已有的 Butler 工作区时，可以直接切换过去，不合并数据。
3. 任何一步失败都回到原工作区，新位置不留半成品。

不做：自动删除旧文件夹、合并两个工作区、迁移 API key 和应用配置（它们在应用数据目录，跟着这台电脑走）、进度条（数据量小，用“忙碌”状态即可）。按用户要求，仓库里不放测试文件。

## 3. 界面

设置页“工作区”卡片：路径下面加“迁移到其他位置…”按钮。点击后弹出系统的选文件夹窗口，选完调用 `workspace:inspect`，按下表处理：

| 选中的文件夹 | 提示 | 按钮 |
| --- | --- | --- |
| 不存在或为空文件夹 | 把工作区迁移到 X。先复制全部数据并检查，再切换。旧文件夹 Y 原样保留。 | 迁移、取消 |
| 已经是 Butler 工作区 | X 里已经有一个 Butler 工作区。切换过去会改用那里的数据，不会和现在的合并，现在这个也不会被删除。 | 切换、取消 |
| 当前工作区本身，或它里面的文件夹 | 说明原因 | 无 |
| 非空且不是工作区 | X 不是空文件夹，请选一个空文件夹，或者新建一个。 | 无 |

- 成功后卡片显示新路径和一句“旧文件夹 Y 还在，确认没问题后可以自己删除”。旧文件夹里 Butler 不管的文件（比如 `.git`）没有搬，一并列出名字。所有页面自动刷新。
- 进行中按钮置灰。失败时错误显示在设置页顶部（沿用页面已有的错误提示），原工作区照常使用。

## 4. 搬什么

只搬 Butler 自己管的顶层条目：`data/`（含撤销历史 `data/.history`，里面都是相对路径，搬过去仍可撤销）、`管家人格.md`、`课表.md`、`今日.md`、`本周.md`、`我的设定.md`、`任务库/`、`记录/`、`归档/`。清单放在 `src/shared/paths.ts` 的 `MANAGED_ENTRIES`，名字以 `render/` 实际生成的为准，实现时核对。

其余顶层条目不碰，沿用“程序不碰工作区里的其他文件”的原则。

## 5. 实现

### 5.1 `src/main/app/migrate.ts`（新增，只依赖 Node）

- `classifyTarget(currentRoot, target)`：返回 `same`、`inside`、`empty`（含不存在）、`workspace`、`occupied`、`file` 之一。比较路径前先 `resolve`，Windows 上忽略大小写。`inspect` 和 `migrate` 共用它，因为确认之前文件夹的状态可能变。
- `createCopyJob(from, to)`：先检查新位置里没有 Butler 的条目（有就拒绝），并算出目标路径上要新建的几层文件夹；这一步不改动任何东西。返回的对象有两个方法：`run()` 把 `MANAGED_ENTRIES` 里源文件夹实际存在的条目递归复制过去（不覆盖），再校验两边的相对路径集合和每个文件的大小，不一致就抛错；`undo()` 只删本次复制出来的条目和本次新建的空文件夹，清不掉就返回没删掉的路径。回退由 `Session` 统一调用，所以复制失败和后面“打开新位置”失败走同一条路径。

### 5.2 `src/main/app/session.ts`

- `migrate(root)`：
  1. 前置检查：已打开工作区、没有别的迁移在进行、`classifyTarget` 为 `empty`，否则抛 `DomainError`。
  2. `createCopyJob` 检查新位置（不改动任何东西），然后进入迁移状态，记下旧路径，`close()`（写完待渲染的视图、停掉文件监听）。
  3. `job.run()` 复制并校验，再 `openAt(目标, null)`（会校验已初始化并写入 `config.json`）。
  4. 任何一步失败：`close()`、`job.undo()`、`openAt(旧路径, null)`，再抛出带原因的错误；旧路径也打不开就在错误里说明并建议重启程序。
  5. 结束后退出迁移状态，`platform.notifyDataChanged('local')`。
- 迁移状态下 `ctx()` 抛“正在迁移工作区，请稍等”，不用“还没有选择工作区”误导。`isOpen()` 为 false，定时检查自动跳过。
- `open(root)`：已经打开了别的工作区时，成功后同样发 `notifyDataChanged('local')`，失败则回到原来的工作区；选的是当前工作区时什么都不做。
- `inspect(root)`：结果新增 `blocked`，是这个文件夹既不能迁移进去、也不能切换过去的原因（当前工作区本身或其内部、是文件、非空且不是 Butler 工作区），可以用就是 `null`。界面先看 `blocked`（显示原因），再看 `initialized`（切换），否则就是空文件夹或还不存在（迁移）。

### 5.3 IPC 与管家

- `src/shared/ipc.ts`：新增 `'workspace:migrate': { req: { root: string }; res: { workspaceRoot: string; skipped: string[] } }`，同时加进 `CHANNELS`；`workspace:inspect` 的返回值按 5.2 扩展。
- `src/main/ipc/index.ts`：`workspace:migrate` 先 `ai.abortAll()` 再 `session.migrate(...)`。路径过 `schemas.folder`。
- `src/main/ai/service.ts`：新增 `abortAll()`，中止所有进行中的管家对话。已经执行的动作都是原子写入，会随数据一起搬走。

### 5.4 界面

- 新增 `src/renderer/src/components/WorkspaceMove.tsx`：状态依次为空闲、检查中、待确认（迁移或切换）、进行中、完成。用设置页传下来的 `useAction`，错误和忙碌状态跟页面其他表单一致。切换复用现有的 `workspace:open`。
- `Settings.tsx` 的工作区卡片渲染它。样式沿用现有类名，不够再补。
- 不加新依赖。README 在“数据在哪”后补一小节“迁移工作区”。

## 6. 出错与边界

| 情况 | 结果 |
| --- | --- |
| 目标非空、是文件、就是当前工作区或在它里面 | 拒绝，什么都没变 |
| 复制失败（磁盘满、没权限、文件被占用） | 回退目标，重新打开旧工作区，错误里带文件名 |
| 校验不一致，或新位置打不开 | 同上 |
| 写 `config.json` 失败 | 按“新位置打不开”处理，同上 |
| 回退本身失败 | 旧工作区数据没动；错误里写出目标里残留的路径，请用户手动删除 |
| 迁移中途断电或崩溃 | `config.json` 仍指向旧工作区，下次启动照常用旧的；目标里可能有残留，可自行删除 |
| 迁移时管家正在对话 | 先中止这次对话，已执行的动作保留 |

迁移本身不修改、不删除旧文件夹里的任何文件。唯一的写入是关闭前把待生成的视图写完，这和平时退出程序一样。

## 7. 验证

- 仓库不放测试。用 `npm run typecheck`、`npm run build`。
- 临时文件夹里用一次性脚本（放在仓库外，用完删除）启动真实的 Electron，设 `BUTLER_USER_DATA_DIR` 和 `BUTLER_DEFAULT_WORKSPACE` 指向临时目录，覆盖四种情况：
  1. 正常迁移，数据和撤销历史都在，旧文件夹原样。
  2. 目标非空被拒，两边都没变化。
  3. 切换到已有的工作区。
  4. 复制中途失败（占用一个文件）能回退，旧工作区继续可用。
- 做完 `npm run dist` 重新打包，装好的版本再走一遍迁移。
